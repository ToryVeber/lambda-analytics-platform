# Data Schemas: Marketing Attribution & Cohort LTV

## 1. Bronze Layer (Raw External Data)
Landing zone for daily raw ad platform snapshots and database dumps stored as immutable files in S3.

### Table: `bronze.ad_spend_raw`
* **Storage Engine:** MinIO S3 Raw Storage (JSON / CSV format)
* **S3 Location:** 
  - `s3://ecom-platform-bronze/google_ads_api/`
  - `s3://ecom-platform-bronze/yandex_direct_api/`
  - `s3://ecom-platform-bronze/telegram_campaigns/`
* **Schema:**

  | Column Name | Data Type | Nullable | Description |
  | :--- | :--- | :--- | :--- |
  | `campaign_id` | String | NOT NULL | Internal ID of the campaign from the source network (or manual tracking ID for Telegram bloggers). |
  | `ad_platform` | String | NOT NULL | Source identifier (`google`, `yandex`, or `telegram`). |
  | `clicks` | Integer | NOT NULL | Total clicks. For Telegram: total link clicks tracked via redirect-shifter. |
  | `impressions` | Integer | NOT NULL | Total impressions. For Telegram: total post views. |
  | `spend_amount` | Decimal(10,2) | NOT NULL | Raw daily spending amount in local currency (or fixed cost per Telegram post). |
  | `extraction_date` | Date | NOT NULL | The daily batch date when this data was logged or fetched. |

### Table: `bronze.crm_orders_raw`
* **Storage Engine:** MinIO S3 Raw Storage (CSV format dump from PostgreSQL)
* **S3 Location:** `s3://ecom-platform-bronze/crm_postgres_dump/orders/`
* **Schema:**

  | Column Name | Data Type | Nullable | Description |
  | :--- | :--- | :--- | :--- |
  | `order_id` | String | NOT NULL | Unique transaction ID from operational database. |
  | `user_id` | String | NOT NULL | Customer identifier to map with clickstream sessions. |
  | `total_price` | Decimal(10,2) | NOT NULL | Total order amount paid by the customer. |
  | `currency` | String | NOT NULL | Currency code (e.g., `PLN`, `USD`, `EUR`). |
  | `status` | String | NOT NULL | Current state of the order (`created`, `paid`, `cancelled`). |
  | `created_at` | Timestamp | NOT NULL | Timestamp when the order was placed in OLTP. |

## 2. Silver Layer (Enriched & Unified Tables)
Apache Spark normalizes financial metrics, converts currencies to USD, deduplicates records, and stores them in the Apache Iceberg transaction format.

### Table: `silver.marketing_spend_unified`
* **Storage Engine:** Apache Iceberg over MinIO S3
* **Schema:**

  | Column Name | Data Type | Nullable | Description |
  | :--- | :--- | :--- | :--- |
  | `campaign_id` | String | NOT NULL | Standardized campaign identifier. |
  | `platform_name` | String | NOT NULL | Unified lowercased platform code (`google`, `yandex`, `telegram`). |
  | `clicks_count` | Integer | NOT NULL | Cleaned daily clicks total. |
  | `daily_cost_usd` | Decimal(10,2) | NOT NULL | Normalized daily cost converted to USD using official historical exchange rates. |
  | `report_date` | Date | NOT NULL | The specific calendar date for the marketing metrics. |

### Table: `silver.orders_historical`
* **Storage Engine:** Apache Iceberg over MinIO S3
* **Schema:**

  | Column Name | Data Type | Nullable | Description |
  | :--- | :--- | :--- | :--- |
  | `order_id` | String | NOT NULL | Unique deduplicated transaction ID. |
  | `user_id` | String | NOT NULL | Cleaned client ID used for behavior and cohort binding. |
  | `revenue_usd` | Decimal(10,2) | NOT NULL | Final net revenue converted to USD (excluding cancelled orders). |
  | `order_timestamp` | Timestamp | NOT NULL | The transaction timestamp. |

## 3. Gold Layer (Analytical Data Marts)
dbt blends unified marketing spend with customer order histories to build analytical marts for cohort valuation and ad profitability.

### Table: `gold.marketing_roi_cohorts`
* **Storage Engine:** ClickHouse (`SummingMergeTree`)
* **Primary Key / Order By:** `(cohort_month, utm_source)`
* **Schema:**

  | Column Name | Data Type | Description |
  | :--- | :--- | :--- |
  | `cohort_month` | Date | The calendar month when this specific group of users made their first purchase. |
  | `utm_source` | LowCardinality(String) | The marketing channel responsible for acquiring this user cohort. |
  | `total_new_users` | UInt64 | Number of unique customers who converted in this cohort via this channel. |
  | `total_spend_usd` | Float64 | Total ad budget spent on this channel during the cohort month. |
  | `cac_usd` | Float64 | Customer Acquisition Cost: `total_spend_usd / total_new_users`. |
  | `ltv_month_1` | Float64 | Cumulative revenue per user generated by this cohort within 30 days of acquisition. |
  | `ltv_month_3` | Float64 | Cumulative revenue per user generated by this cohort within 90 days of acquisition. |
  | `roas_pct_m3` | Float64 | Return on Ad Spend at Month 3: `(ltv_month_3 / cac_usd) * 100`. |
  | `updated_at` | DateTime | Timestamp of the last dbt pipeline run. |
